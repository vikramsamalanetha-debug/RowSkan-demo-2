# RowSkan native candidate 0.4

Vehicle inventory by [LIT America](https://litamerica.net).

## Run the app without installing development tools

Open the repository's **Actions** tab and choose a successful **RowSkan release checks** run. Its artifacts include an Android debug APK and complete Windows/Mac preview packages. These are testing distributions, not store-signed production installers. Keep the complete Windows folder together; it includes the SQLite runtime. Real-device camera and upgrade tests remain necessary.

## Included

- On-device SQLite inventory and private application photo files.
- Phone system camera capture, gallery selection, VIN barcode scan and NHTSA lookup.
- Recoverable unfinished intake entries, including photo selections.
- Revision checks preventing stale edits from overwriting newer changes.
- Solo phone-owner management; team phones cannot delete saved records/photos through app operations.
- Recoverable native vehicle deletion and local audit events.
- Password-encrypted .rowskan exports; additive ZIP/legacy import with prevalidation and transactional inventory writes.
- SQLite schema migration from the initial version.

## Boundaries

Native device pairing and encrypted sync are implemented for a configured relay. Real-device internet acceptance, owner-key recovery, optional cloud storage/billing and store distribution remain release work. Local permissions do not protect against a device owner tampering with local files. Local databases and photos rely on the device operating system protections; exported backups are separately encrypted.

Browser .rowskan-web backups and native .rowskan backups are separate formats. They are not cross-edition sync. This build limits native backup contents to 200 MB; larger production inventories need streaming exports. Deleted records and drafts are excluded from exports. Removed-photo file retention cleanup remains release work.

## Build from source

Install Flutter stable (CI uses 3.35.7), Python 3 and your platform's native tools. In this directory run:

```
flutter create --org net.litamerica --project-name rowskan --platforms android,ios,windows,macos .
python tool/configure.py
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
```

Then use `flutter build windows --release`, `flutter build macos --release`, or `flutter build apk --debug`. Windows requires Visual Studio with Desktop development with C++; Mac/iOS requires Xcode, CocoaPods and Apple signing configuration for real-device releases. iOS minimum target is 15.5. Standard runners are generated by Flutter; do not commit credentials, certificates or real inventory.

See [release notes](../RELEASE.md) for acceptance gates before commercial launch.


## Pair and synchronize native devices

1. Host the supplied [relay](../sync-relay/README.md) on an existing server with TLS. Hosting is not provisioned and no Firebase billing is enabled. Use a `wss://` URL ending in `/relay`.
2. Open **Sync** on the owner desktop, enter the endpoint and device name, and create a workspace. A solo phone owner may create their own workspace.
3. On another device, generate a pairing request. Transfer it directly to the owner. The owner pastes it, selects capture or a trusted desktop manager, and generates an approval.
4. Transfer that private approval to the requesting device and accept it there. Approvals contain the workspace discovery secret; do not post them publicly. Compare device names and verify the request through a trusted channel.
5. Tap **Connect / Sync** on both devices. Keep apps open and online. Queued edits, photos and GPS pins transfer automatically. Existing local inventory is shared when pairing; use an empty app installation if you do not want to share pre-existing data.
6. Review simultaneous-edit conflicts on the owner device. Keep the local version or choose the incoming version. Revoking all approvals rotates workspace access for future synchronization; reapprove remaining devices. Copies already saved elsewhere cannot be erased remotely.

The signing seed and pairing profile use platform secure storage. Losing the owner device or its key currently requires starting a new workspace on a fresh installation and re-pairing; there is no owner-key recovery flow. Encrypted inventory backups do not include signing identities or pairing profiles. Preserve an accessible owner device and tested inventory backups.

The relay cannot read encrypted record/photo payloads but can see connection addresses, opaque room identifiers, workspace identifiers, device identifiers, timing and sizes. Queues and partial photo files live on the devices. Retained history/photos and abandoned partial files grow disk use; automatic pruning is not implemented. App/database tampering by the local device administrator is outside the authorization boundary.
